# 画面（web/）

逃げ道の点検屋の画面。HTML・CSS・JavaScript だけで作成した（ライブラリとビルドツールは使わない）。`web/intro/`（はじめに）と `web/story/`（仕組みの説明）は、説明用のアニメーション。

画面の文言は、プロジェクトの用語集と文章のルールに従う。画面への表示は `textContent` で行い、`innerHTML` は使わない。インラインの `<script>`・`style` 属性も使わない（CSP のため）。

## 起動と確認

### サーバーなし（サンプルデータで動かす）

サーバーに接続できないときは、`web/mock/` のサンプルデータ（架空の人物）の JSON で動かす。

```bash
.venv/Scripts/python.exe -m http.server 8765 --bind 127.0.0.1 --directory web
```

ブラウザ（Chrome。スマートフォンの画面サイズ）で `http://localhost:8765/` を開く。`/api/login` に接続できないときは、自動でサンプルデータの動作になり、画面の上に「試験用: サーバー未接続」と表示する。このとき、合言葉は空でなければ何でもよい。`?mock=1` を付けると、サーバーを試さずにサンプルデータで動く。

### サーバー（`app/server.py`）と動かす

サーバーが `web/` を `/` で配信し、`/api/...` に答えれば、同じ画面がサーバーで動く（サンプルデータの表示は消える）。

## 試験・撮影用の URL

| URL | 動作 |
|---|---|
| `/?mock=1&autologin=1` | 合言葉を省いて、サンプルデータで開く |
| `#/sample?id=yamada&stage=checked` | 山田さんの、点検が終わった状態の「点検」の画面を開く |
| `#/sample?id=yamada&stage=checked&goto=fix` | 同じ状態から「改善案」の画面を開く |
| `#/sample?id=yamada&stage=improved&goto=print` | 改善が終わった状態から「印刷」の画面を開く |
| `dev/frame.html?w=360&h=2600&p=/sample?id=yamada&stage=checked`（`p` の `?`・`&`・`=` は `%3F`・`%26`・`%3D` にする） | 画像を撮る用。幅 `w`（既定 390px）・高さ `h` の枠（iframe）の中でアプリを開く。headless の Chrome は、窓の幅を 500px 未満にできないため。`do=`（`listening`・`dialog`・`error`・`running`・`verify2`・`verifyDone`・`savedHome`）で、開いたあとに特別な状態を作る。`nobanner=1` で、サーバーなしのときだけ出る試験用の帯を隠す。`measure=1` は、画面の全体の高さを `body` の `data-h` に入れる（`h` を小さくして開く） |
| `?audit=1`（コンソールで `await ECAudit.runAll()`） | 主な 12 画面を順に開いて、文字の大きさ・ボタンの高さ・コントラスト・横のはみ出しを確認する（結果が空なら問題なし。幅 360px と 390px で確認した） |

`id` は `yamada`（山田さん）、`okabayashi`（岡林さん夫婦）、`takemura`（竹村さん）。`stage` は `start`（話す手順から）、`talked`（聞き取りのあと）、`checked`（点検のあと）、`improved`（改善のあと）。`goto` は `talk`・`check`・`fix`・`verify`・`print`。

## 画面の流れ

合言葉 → ホーム →（新しい計画を作る: 自宅の場所を地図で決める／サンプルデータ）→ 話す → 点検 → 改善 → 点検（もう一度）→ 確認 → 印刷

「記録」（AI の書き込みを、コードが止めた記録）は、点検の画面は、結果の概要のカードの中から、話す・確認の画面は、下の行から開く（`#/audit?from=check`）。

- 下の大きなボタンは、1 画面で 2 つまで（話す・それでいい など）。「戻る」は画面の上に常に表示する。一覧の行と、「読み上げを止める」は、ボタンの数に含めない（高さは 64px 以上にしている）
- 判定は色だけで伝えない。「○ 間に合う（◯分の余裕）」「△ 余裕が少ない」「× 間に合わない（◯分不足）」の印と文字を付け、タイムラインは区間ごとに模様を変えている
- 音声入力が使えないブラウザや接続では、文字の入力欄を出す（E1）。使えるときも、話す画面の「文字で入力する」で切り替えられる（「声で話す」で戻る）。失敗したときは「もう一度」を出し、入力した欄は消えない（E3）
- 取得できない値は「取得できませんでした」と出し、表示は乱れない（E4）。すべてのシナリオで間に合わないときは、その旨と、印刷できることを出す（E5）

## デザイン（色・文字・余白）

公共のサービスとして、なじみやすく、使いやすく、信頼できる見た目にする。高齢の民生委員が使うので、文字とボタンを大きくし、色だけで意味を伝えない。

- **基調色は藍**（公共の落ち着き）。背景は薄い灰、本文は濃い紺がかった黒。本文と背景のコントラストは、すべて 7:1 以上（`audit.js` で確認する）
- **判定の色**は、安全色の考え方（緑＝安全、黄＝注意、赤＝危険）。色のほかに、記号（✓・!・×）と文字を必ず付ける。印刷は白黒でも区別できるよう、記号を文字（○△×）にする
- **文字**は UD フォントを優先する（BIZ UDPGothic → Hiragino Sans → Noto Sans JP → Yu Gothic UI → Meiryo → sans-serif）。外部のフォントは読み込まない
- 色・文字の大きさ・余白・角・影は、`style.css` の先頭の CSS の変数（デザインの変数）にまとめ、全画面で使う。アイコンとロゴは自作の SVG（`icons.js`、`icon.svg`）で、ライブラリは使わない
- 画面の上に、今どの段階かを示す（話す → 点検 → 改善 → 確認 → 完成）。終わった段階には ✓ が付く。各画面が `EC.app.setStage(1〜5)` で伝える
- 実在の機関の名前やロゴは使わない。ホームに「試作版」、サンプルに「デモ用の架空の人物」と出す

## API の約束（サーバーとの接続）

`api.js` の先頭にも同じ内容を記載している。計画（plan）は `tools/plan_model.py` の形で、自宅などの座標を含む。本名と電話番号は、計画にも送信する文字にも含めない（端末の中だけ。送信前に仮名に置き換える）。

| メソッドとパス | 送るもの | 受け取るもの |
|---|---|---|
| `POST /api/login` | `{ passphrase }` | `{ token }`。以後の API には `Authorization: Bearer` を付ける。401 なら合言葉の画面にもどる |
| `POST /api/interview` | `{ plan, utterance, speaker, asked_field? }` | `{ plan, next_question, changed_fields, next_field }`。`asked_field` には、前の応答の `next_field` を送る（答えが得られなかった欄を、同じ質問で繰り返さない）。確認の画面で欄に答えるときは、その欄を送る |
| `POST /api/check` | `{ plan }` | `{ job_id }` |
| `GET /api/jobs/{id}` | | `{ job_id, state, events, plan, error }`（1.2 秒ごとに問い合わせる） |
| `POST /api/approve` | `{ plan, fix_id, by }` | `{ plan, results }`。`results` は、承認の直後にコードが計算し直したシナリオの結果（ID → 結果）。あれば、Claude に点検させ直さず、すぐに「改善の結果」を出す。無いときは、`/api/check` で点検し直す |
| `POST /api/verify` | `{ plan }` | `{ issues, plan }`（`issues` だけ、または配列でもよい）。`chk_short_◯` の項目は、点検のカードごとの「相談する」の確認（`issue_id` が `consult_<finding_id>`）で扱う |
| `POST /api/finalize` | `{ plan }` | `{ ok, reasons, plan }`（サーバーが提供する）。サーバーに無い（404・405・501）ときは、未解決の項目が残っていないかを画面で確認する |
| `POST /api/facts` | `{ plan, target: "home" }` | `{ facts, shelters, sources }`（計画（座標を含む）を送るため POST）。失敗したときは、地図は点と線だけにする |
| `GET /api/audit?plan_id=` | | `{ entries: [{ at, agent, tool, decision, args, result, reason }] }`。「記録」の画面に、コードが止めたものを、時刻・エージェント・理由で出す。`decision` は、`deny`（フックが止めた）・`result`（通した）・`error`・`info`。`error` で理由があるもの（計算のコードが危険な改善案を断った）も、止めたものに入れる。`args` と `result` は、短くした JSON の文字（途中で切れていることがある）。`agent` は interview・redteam・verify・server。サーバーが無いときは、サンプルの記録（`mock/audit.json`） |
| `GET /api/samples`、`GET /api/samples/{id}` | | サンプルデータ（架空の人物）。`{ case_id, title, alias, area_label, home, talk[], form{}, supporters[] }` の形（A の `data/samples/`）。画面は、これから計画を作る（「話す手順から」は、`talk` を話す内容の例にする。「途中から」は、`form` を欄に入れ、`talk` を出典にする）。無いときは `mock/` の JSON |

画面が前提にしている計画の形:

- `plan.home`、`plan.supporters[].location`（地図に描く）、`plan.fields.shelter.value` は `{ shelter_id, name, kind, distance_m, distance_method }`。避難先の位置は `facts.shelters[].point`
- `findings[].explanation` と `fixes[].explanation` は、コードがプレースホルダーを埋めた文。無いときだけ、画面が `explanation_template` の `{need_min}` `{avail_min}` `{margin_min}` `{shelter_name}` `{saved_min}` を、結果の値で置き換える
- 分の表示は安全側に丸める（不足は切り上げ、余裕は切り捨て）。画面では計算しない
- `fixes[].fix_type` は `FIX_TYPES` にあるものだけ表示する（S-03 の二重の防止）。いまの避難先への「避難先を変更する」は出さない
- 判定が `cannot_compute` のときは、`reason_code`（`NO_ARRIVAL_TIME`・`NO_SHELTER`・`NO_HOME`・`NO_WALK_SPEED`・`NO_SUPPORTER`）を文にする。ほかの値は「必要な値が足りません」と表示する

### CSP（サーバーが設定するヘッダー）

画面は、次の CSP で動く。

```
default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' https://cyberjapandata.gsi.go.jp https://disaportaldata.gsi.go.jp; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'
```

`img-src` の 2 つは、地理院タイル（淡色地図）と、津波浸水想定のタイル（高知県）。地図の出典の表示（「地理院タイル」とタイル一覧へのリンク、「津波浸水想定: 高知県（ハザードマップポータルサイト）」）を、地図の下に付けている。
